## The project: a sales assistant for Chinook

The capstone we’ll build is a **sales assistant** for **Jane Peacock**, a sales rep at **Chinook**, an online music distributor. It helps her work her “book of business”: it reads quote requests from a **mock Gmail-style inbox**, looks up customers and prices in the **Chinook sales database**, drafts replies for her to approve, writes a weekly music newsletter, and reports on how her territory is doing.

It’s a single deep agent, but a complete, realistic application.

---

Over the last four modules you met the pieces of Deep Agents one at a time: the model and tools, skills and `AGENTS.md`, the filesystem, the interpreter, the sandbox, human-in-the-loop, and subagents. This module is the capstone: a single, real project that uses **all** of them together.

A key takeaway from this module: creating a deep agent requires very little code. Most of the agent’s behavior is determined by **text**: the skills and the `AGENTS.md` file.

## Every feature, and where this project uses it

Here’s the whole toolkit from the course, mapped to where the sales assistant puts each one to work:

- **Subagents**: `chinook-analyst` (owns the database), `inbox-manager` (owns mail), `quote-reviewer` (sanity-checks a quote), and, when web search is configured, `genre-researcher` (newsletter research). Each is a specialist with its own tools.
- **Parallel subagents**: with web search configured, the newsletter fans out one `genre-researcher` per genre, all at once, then stitches the segments together.
- **Skills + `AGENTS.md`**: a plain-text operating manual plus one playbook per task (RFQ quote, newsletter, territory report).
- **Filesystem**: skills, `AGENTS.md`, the quotes ledger, newsletter HTML, and territory report live in the assistant’s local `FilesystemBackend` during local development.
- **Interpreter**: exact quote math: line totals and the volume discount, computed rather than guessed.
- **Human-in-the-loop**: approval gates on the two consequential actions: saving a mail draft and adding a new customer.
- **MCP**: mail access through the local mock MCP server used in this module. A real Gmail/OAuth integration would be a later extension, not part of the shipped lab.
- **Todo list** *(optional)*: `write_todos`, opt-in via `TodoListMiddleware`, can sequence a multi-step task like the RFQ flow so the agent keeps its place.

Over the rest of the module, you’ll build this assistant and run it.
