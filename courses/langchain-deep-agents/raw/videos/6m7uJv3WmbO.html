So far, you've run every agent as a script. You invoke it at the command line, it runs, and it returns a result. Often, though, an agent wants to be deployed. Consider a chat agent. You have a chat user interface, and that UI calls the agent over an HTTP interface. The agent runs and returns a result. In the next turn, the user makes another request, and they expect the same agent to be there, remembering the conversation they've been having.

So the agent has to run behind a web API, not inside a Python script you invoke by hand. Let's look at what it takes to make that possible

All of this is available locally

With langgraph dev, which is part of the LangGraph CLI package, It gives you a cloud deployment-like environment right on your laptop

So to reach your agent over HTTP, you need a few things running behind it, and LangGraph Dev wraps your agent in all of them. You'll need an HTTP API for endpoints, persistence, so state is stored between runs, a store for long-term memory, and a task queue that receives runs and schedules your deep agent to execute them

Studio here reaches all of this the same way any chat UI would, over HTTP

so what is Studio? It's basically a chat and debug interface. It gives you a chat panel to talk to your agent, plus a graphical debugger, and you'll see both in the lab later
