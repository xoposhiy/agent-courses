Agent memory splits into two scopes: short-term and long-term

Short-term memory is the running message history for a single thread. It's tracked automatically by the checkpointer and does not persist beyond that thread Long-term memory is what the agent has learned that should carry over across threads, things like user preferences, project conventions, and recurring facts. It's tracked in a persistent store or file system and separate from any one thread's message history.

The distinction here is scope, not lifetime. A checkpointer can be backed by a real database and outlive the process. It's still short-term though, because that history only exists inside the thread that created it. Long-term memory is visible to any thread that matches its scope, same user, same workspace, whatever you choose, regardless of which thread wrote it
