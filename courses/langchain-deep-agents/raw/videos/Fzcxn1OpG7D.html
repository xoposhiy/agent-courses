Single vs Composite + Permissions

The simplest setup is one backend passed directly to create_deep_agent. Here it's StateBackend, the default. All file system tool calls land in thread state Composite is for when different files have different requirements. You define path prefix routes, and anything that doesn't match falls through to the default.

Here, reference goes to a local file system backend, real files on disk, while everything else stays in state backend. The agent never sees the routing. It just calls read file and the backend handles the rest

In code, the single backend case is one argument, backend equals StateBackend. If you want local disk instead

Swap it for file system backend. Same interface, but different storage

CompositeBackend takes a default and a routes dictionary. That's the entire routing configuration One route sends reference to a file system backend pointed at a local directory. Everything else falls back to state backend.

permissions are a separate layer enforced in code. The model cannot bypass them

Pass a list of file system permission rules to create Deep Agent. And the rules are evaluated in order of the first match winning. If nothing matches, the operation is allowed. And each rule has three fields

Operations, read or write, paths, which are glob patterns, and mode, allow, deny, or interrupt Interrupt is the same human-in-the-loop pattern instead of silently blocking, it pauses and surfaces the pending action for human approval
