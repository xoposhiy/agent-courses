Context Isolation + Sync & Async

Let's look more closely at what actually happens at the handoff boundary between the main agent and a subagent, because this is what makes subagents a context engineering tool on the left, the main agent has accumulated a long message history across many turns. On the right, the subagent starts with completely fresh context. When the main agent delegates, one message crosses the boundary, the task assignment.

The subagent does not inherit the main agent's history. It just gets its assignment. The subagent then runs autonomously, taking as many steps as it needs, using its own tools, making its own LLM calls until the task is done. Then one message comes back, its final result. There's no back and forth with the main agent mid-task.

One in, one out

There are three things to notice here

First, the subagent gets one message describing its task and nothing else. No history, no accumulated context. It starts fresh every time.

Secondly, the subagent defines its own tool set. Think about a database expert with dozens of specialized tools. Putting those behind a subagent means every one of those tool descriptions stays out of the main agent's context it sends the task and gets back an answer.

Thirdly, the key payoff. A large messy subtask gets compressed into a single clean result. As long as the subagent is told to return a concise summary, none of its internal steps or tool calls land in the main agent's context

The main agent stays focused on coordination even as the work accumulates behind the scenes.

subagents can run in two modes, and the choice comes down to one question. Does the main agent need the result before it can keep going? In synchronous mode, the main agent blocks and waits until the subagent is finished It's the simpler model, but the conversation pauses while the work happens.

In asynchronous mode, the subagent runs in the background, and the main agent launches the job, stays responsive, and checks back later to collect the result. This course uses synchronous subagents in the hands-on lab. Asynchronous subagents are for production and background workflows where the main agent should stay responsive while longer work continues elsewhere.
