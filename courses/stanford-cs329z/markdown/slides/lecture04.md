Why Tools?

What LLMs can't compute

1. Arithmetic at scale
2. Multi-step logical deduction
3. Exact, verifiable operations

What LLMs never saw in training

1. Long-tail facts
2. Post-cutoff events
3. Private and proprietary data

What LLMs can't reach

1. Non-language interfaces (e.g., APIs, databases)
2. The physical world
3. Live state (e.g., time, prices, sensors)

Berkeley Function Calling Leaderboard

• BFCL: a comprehensive evaluation framework of a LLM’s ability to 
invoke functions (also known as tool calling)

• Evaluation:
• Abstract syntax tree (AST) based offline evaluation
• Execution of the function for real-world evaluation
• State based evaluation for multi-step and multi-turn function calls

• Datasets:
• Sourced from real-world use-cases
• Establish different taxonomies for function calling
• Evaluation Python, C++, Java, SQL, …
• Tests relevance and irrelevance (none of the function choices provided are relevant to the user query)

## Page 67

Failure Modes in Tool Use

Single call

Selection: wrong tool, or a tool 
when none was needed

Arguments: made-up fields, 
wrong types or units

Hallucinated tool: calls an API 
that doesn't exist

Multi-step chain

Sequencing: skips a prerequisite 
call, wrong order

Recovery: retries the same 
failing call instead of backing off

Conversation

Policy: acts where the rules say 
not to

Interaction: assumes instead of 
asking the user

Non-determinism: passes once, 
fails on the retry (pass^k)
